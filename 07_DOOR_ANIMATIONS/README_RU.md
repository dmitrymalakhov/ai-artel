# Двери AI Artel

Дополнение к исходной офисной сцене: деревянная дверь кабинета руководителя, раздвижные стеклянные двери переговорной и входная дверь офиса. **24 отдельных прозрачных кадра**, по 8 поз на каждую из трёх дверей; у каждой есть закрытое состояние, открытие, открытое состояние и закрытие. Закрытие использует те же кадры в обратном порядке.

Откройте **index.html**: все три двери анимированы в исходном офисе, персонажи проходят в комнаты, заходят снаружи в офис и возвращаются. Есть крупные планы, ручной проход, автопроход и пауза. Просмотр работает прямо с диска без сервера и без установки библиотек. Это демонстрация подключения; код целевого игрового приложения в репозитории отсутствует.

## Что передать агенту

- Всю папку **07_DOOR_ANIMATIONS** и **06_CHARACTER_ANIMATIONS**.
- **manifest.json** — координаты, размеры кадров, привязки, направления прохода, длительности и правила доступа.
- **scene/character_free_all_doors_open.png** — актуальный фон с тремя очищенными проёмами и свободным подходом к входу. Изменены пять областей из manifest: две внутренние двери, входные створки, перенесённый шкаф и зона отдыха со сдвинутым креслом; за их пределами пиксели совпадают с исходным фоном. Старый character_free_doors_open.png сохранён для версии с двумя дверями.
- **doors/<id>/atlas.png + atlas.json** — прозрачные горизонтальные атласы; **frames/** — отдельные PNG.
- **doors/<id>/frame_foreground.png** — исходные неподвижные косяки и верхняя направляющая для перекрытия персонажа.
- **doors/<id>/animations.json** — четыре состояния/действия двери.
- **tools/door-controller.mjs** — самостоятельный контроллер очереди, прохода и закрытия для JavaScript. Другой движок может повторить эту логику.
- **AGENT_HANDOFF.md** — инструкция по внедрению и связи дверей с персонажами.
- **previews/** — демонстрация и проверенные снимки.
- **docs/GENERATION_PROMPTS.json**, **EXTRACTION_AUDIT.json**, **VALIDATION.json** — задания генератору, параметры упаковки и проверки.

## Размеры и поведение

Координаты относятся к сцене **1254×1254**, Y направлена вниз. Положение персонажа — точка ног. Если сцена масштабируется, масштабируйте фон, двери, привязки и точки маршрутов одинаково. Для пиксель-арта отключите сглаживание.

Кабинет: кадр **128×160**, атлас **1024×160**. Переговорная и вход в офис: кадр **256×192**, атлас **2048×192**. Не использовать настройки кадра 128×128 из набора персонажей для дверей.

Открытие и закрытие длятся по **800 мс**. Дверь разрешает проход после полного завершения открытия; после освобождения зоны держится открытой ещё **1100 мс**. Для примера выбран безопасный проход по одному персонажу. Препятствие или новый запрос во время закрытия запускает открытие с текущей позы.

Новая графика створок и очищенных проёмов нарисована встроенным **image_gen** с исходной сценой в качестве референса. Исходный фон сохранён; готовые кадры механически извлечены, приведены к общим привязкам и упакованы. Переговорная и внешний вход используют раздвижное открытие; кабинет — правую петлю. Это новые анимационные варианты дверей, а не точная копия каждого пикселя исходной створки.

Атласы не нужно создавать повторно. Файлы sources/ сохраняют исходную генерацию; для внедрения используйте doors/. Реальное приложение должно предоставить маршрутизацию, коллизии, события удаления персонажей и масштаб сцены. Эти части проверяются после подключения в целевом проекте.

## Обновлённая сцена

Для входной двери **office_entrance** сторона corridor — внешний коврик/улица, room — офис. Сотрудник ждёт снаружи полного открытия, входит, затем идёт по своей задаче. Шкаф перед входом перенесён выше; обнови коллизии и маршруты по актуальному фону. Выход обратно проходит через ту же очередь.

Мягкая мебель, телевизор и приставка находятся в **../08_LOUNGE_AND_SOCIAL**. Для полного обновления передай агенту актуальные 06, 07 и 08, начни с **08_LOUNGE_AND_SOCIAL/DEVELOPER_START.md**. Архив дверей этой версии: **AI_ARTEL_DOOR_ANIMATIONS_V2.zip**; V1 остаётся историческим.
